# 符号与解释

模型的职责是输入「符号」（Sign）列表，续写这个符号列表。
也就是返回对输入符号列表的「解释」（Interpret）。

具体实现为 `Model` 的 `interpret` 接口函数：

- 输入符号列表：`input: Array<Sign>`；
- 返回一个包含符号的事件流：`AsyncIterable<ModelInterpretEvent>`。

```typescript
export type Model = {
  providerName: string
  name: string
  interpret: (
    input: Array<Sign>,
    options?: ModelInterpretOptions,
  ) => AsyncIterable<ModelInterpretEvent>
}
```

所返回的包含符号的事件流：

```typescript
export type ModelInterpretEvent =
  | { type: "delta"; delta: SignDelta }
  | { type: "sign"; sign: Sign }
  | { type: "error"; error: ModelError }
  | { type: "usage"; usage: ModelUsage }
```

# 智能体的工具调用循环

`Agent` 包含一个具体的 `Model`：

```typescript
export type Agent = {
  model: Model
  toolRouter: ToolRouter
  getContext: () => Promise<Array<Sign>>
  appendContext: (signs: Array<Sign>) => Promise<void>
}
```

`Agent` 的 `agentInterpret` 函数与 `Model` 的接口很相似。
差异在于 `Model` 的 `interpret` 接口的职责是：

- 单次调用模型来续写符号列表，
  也就是把「符号过程」（Semiosis）向前推进一小步。

而 `Agent` 的职责是：

- 调用 `Model` 的 `interpret` 接口函数；
- 看看所返回的结果符号是否包含「工具调用」；
  - 若是：就调用工具，把工具返回的结果作为新符号添加在符号列表后面；
    然后回到开始，循环调用 `Model` 的 `interpret`。
  - 否则：就结束循环。

也就是说 `Agent` 的职责是：
以 `Model` 的 `interpret` 为基础，
来形成「工具调用循环」：

```typescript
export async function* agentInterpret(
  agent: Agent,
  input: Array<Sign>,
  options: AgentInterpretOptions = {},
): AsyncGenerator<AgentInterpretEvent> {
  // ...
}
```

其中 `AgentInterpretEvent` 与 `ModelInterpretEvent` 很相似：

```typescript
export type AgentInterpretEvent =
  | { type: "delta"; delta: SignDelta }
  | { type: "sign"; sign: Sign }
  | { type: "input-persisted" }
  | { type: "error"; error: ModelError }
  | { type: "usage"; usage: ModelUsage }
  | { type: "step-start" }
  | { type: "step-end" }
```
