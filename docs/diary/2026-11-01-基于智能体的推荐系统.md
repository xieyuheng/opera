# 基于 AI agent 的餐品/饮品推荐系统

设计一个专门用于餐饮门店（比如咖啡馆）的
基于 AI agent 的餐品/饮品推荐系统。

用户在局域网扫码，可以向 agent 描述需求，
agent 可以推荐餐品/饮品。

- 推荐所用的信息来源，是店员所维护的一个「知识库」。
- agent 做推荐时，可以有专门的 tool 来生成「推荐卡片」在前端渲染。

AI 推荐流程：

- 用户在门店扫码，无需登录。
  - 不同桌子可以贴不同的码，这样可以知道是哪一桌在点餐。
- 描述需求，agent 继续询问细节或生成「推荐卡片」。
- 用户可以把卡片给店员看；
  也可以把卡片设计为有状态的，
  点击卡片上的按钮，可以把信息同步给店员。
  - 顾客的选择被结构化保存了；
  - 店员不需要重新询问一遍；
  - 不需要接 POS；
  - 收款仍然走门店原来的收款码；
  - AI 不算真正完成交易，只负责把“意图”准确传过去。
- 店员用已有的第三方点单系统，确认并收款。
- 生成推荐卡片之后，对话还可以继续聊。
  用户如果有关于餐品的问题，
  或者有关于门店的问题，
  可以继续聊。

交互例子：

1. 顾客扫码，问：“想喝点不太甜的，有什么推荐？”
2. Agent 推荐 1–3 款，并说明理由。
3. 顾客点其中一张卡片，进入规格确认：杯型、冰量、糖度、加料、桌号。
   - 或者可以继续通过对话，让 agent 完善选择。
4. 卡片底部有明确按钮：“提交给店员”。
5. 提交后生成一张订单条，比如：
  * 2 号桌
  * 燕麦拿铁，大杯，少冰，半糖
  * 顾客备注：不要肉桂粉
  * 价格：28 元
  * 推荐来源：AI 推荐
6. 店员确认端收到订单条，点“接单”。
7. 顾客端显示：“已通知店员，请稍候。付款请使用柜台收款码。”
8. 店员在原有点单系统完成录入和收款。

这条链路里，AI 不负责付款，店员保留最终确认权。
这既降低你的风险，也符合门店现有习惯。

作为独立开发者，怎么找到愿意配合的门店？
不要找大型连锁。找那种：

* 老板或店长自己就在店里；
* 菜单不算特别复杂；
* 已经在用扫码点单或收款码；
* 店员愿意每天更新售罄信息；
* 愿意给你一个柜台平板或手机做确认端；
* 愿意让你观察一到两周真实使用情况。

软件包：

- 知识库。一个知识库就是一个文件夹，
  核心是一个 markdown 编辑器。
  - 在这里可以设置 AI 智能体的「人设」，
    也可以预览「推荐卡片」，或测试「推荐流程」。
  - 店员对「知识库」的维护，也可以通过与 agent 对话完成。
- 查询知识库的 tool，与生成推荐卡片的 tool。

# 推广

回想 mimor app 中，对笔记的「主动回顾」功能。
对笔记的推荐，也是一种「卡片推荐」。

所谓「卡片推荐」，就是不只是用文字表达出所推荐的内容，
而是把所推荐的内容，渲染成可以交互的卡片。

这种基于本地小型知识库的，
利用智能体实现的，
卡片式的内容推荐系统，
是大有应用场景的。
