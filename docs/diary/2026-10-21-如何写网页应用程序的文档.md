# 例子

网页应用程序也是需要文档的，
这方面做的不错例子是「浮墨笔记」的文档：

- <https://help.flomoapp.com>

网页应用程序，最好能有良好的引导性设计，让用户直接上手可用。

但是像其他工具类程序一样，还是文档的。

「浮墨笔记」的文档像是与用户交流的窗口。
里面有大量的截图用来「介绍功能」「推荐用法」等等。

# 截图

对于网页类应用程序来说，
初见的用户最想看到的是：
「程序具体用起来是甚么样的」。

这就是最适合用「截图」加「讲解」来实现的。

配合截图，我们可以展示用法、讲解功能，
甚至讲解某些设计背后的设计思路。

# 历史

人们一般建议图片不要放在 git 版本控制系统中，
而是要独立实现一个「内容管理系统」，
来处理图片上传与连接。

但是这也许不是好实践。

虽然图片相对于文本会占用更多硬盘，
并且随着应用程序的迭代，截图会变化，
但是截图就直接记录在 git 版本控制系统之中。

这样，我们可以有一个专门的页面，
来展示应用程序的设计随时间的变化。
